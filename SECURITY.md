# Security Policy

Brok-AI takes the security of its projects and users seriously. We appreciate responsible reports that help us identify and address vulnerabilities.

## Supported Versions

Security fixes are generally prioritized for actively maintained releases and branches. The support status of a specific version is defined by the relevant project's release notes and maintenance documentation.

Please include the affected version, branch, or commit in your report.

## Reporting a Vulnerability

**Please do not report exploitable vulnerabilities through public GitHub issues, discussions, or pull requests.**

Instead, use GitHub's private vulnerability reporting feature for the affected repository if it is enabled. If private reporting is unavailable, contact the repository or organization maintainers privately through GitHub and request a secure reporting channel.

Include, where possible:

- A description of the vulnerability and its potential impact
- The affected repository, version, branch, or commit
- Steps to reproduce or a proof of concept
- Any relevant logs or screenshots, with secrets and personal data removed
- Suggested mitigations, if known

Do not include real credentials, API keys, private user data, or information belonging to others.

## Response

Maintainers will review reports, may request additional information, and will work to assess and address confirmed issues. Response and remediation timelines depend on severity, reproducibility, and project capacity.

Please allow maintainers a reasonable opportunity to investigate and coordinate a fix before making vulnerability details public.

## Scope

This policy covers security vulnerabilities in software maintained by the Brok-AI organization. For third-party services, dependencies, or unrelated infrastructure, please contact the responsible maintainer or provider.
